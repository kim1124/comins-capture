# 0.0.1 구현 상태·배포 품질 벤치마크

측정일: 2026-10-15 KST. 요청 범위는 구현 여부 확인과 품질·성능 판정이며 제품 수정·배포는 수행하지 않았다.

후속 갱신: 같은 날 [잔여 항목 확인](2026-10-15-release-followup.md)에서 npm 런타임 감사 취약점0건·후보80파일 및 tarball 해시 불변·용지24개 기하 통과를 확인했다. JIS 공식 원문 대조는 계속 미완료다. 아래 감사 승인 대기 서술은 최초 벤치마크 당시 기록이며, 현재 감사 상태는 이 후속 결과가 대체한다. output/benchmarks의 원본 report·manifest는 최초 측정 기록으로 보존한다.

## 결론

**0.0.1 범위의 실행 기능은 구현되어 있다. 고정 tarball을 사용한 실제 Chrome의 제한된 정적 DOM 기능·화면 품질·반복 안정성 검사는 통과했다. Chrome 한정 기술 품질은 조건부 합격이며, 즉시 공개 배포 준비 완료는 보류한다.** 미구현 이월 기능을 다시 추가하거나 Safari 실패를 해결한 결과가 아니다.

출시 전 확인 항목은 JIS P 0138 원문의 치수 대조, 승인 대기 중인 알려진 런타임 취약점 조회다. 실제 0.0.1 버전·공개 설정·고정 commit 및 publish 절차는 이번 벤치마크와 별도다. 현재 private:true·0.0.0-dev.0이다. 이미 수행한 npm audit가 통과한 것으로 표시하지 않는다.

## 성능 실측

아래는 capture와 기본 PNG를 합친 시간이다. capture p50과 출력 p50의 합은 전체 p50과 다를 수 있다.

| fixture | 노드 | 표본 | capture p50 ms | PNG p50 ms | 전체 p50 ms | 전체 p95 ms |
|---|---:|---:|---:|---:|---:|---:|
| invoice-warm | 64 | 10 | 172.4 | 11.5 | 183.6 | 198.9 |
| geometry-warm | 5 | 10 | 18.5 | 5.5 | 23.8 | 26.2 |
| dense-warm | 145 | 10 | 296.4 | 11.5 | 306.7 | 438.0 |

페이지 최초 명세서 캡처는 capture203.8ms + PNG29.1ms = 전체232.9ms다. 뒤 fixture의 첫 capture는 이미 로드된 엔진을 공유하므로 각각을 완전한 cold start로 해석하지 않는다.

기존 snapshot 재출력은 아래와 같다. 이 시간에는 최초 capture가 포함되지 않는다.

| 출력 | 표본 | p50 ms | p95 ms | 파일 bytes |
|---|---:|---:|---:|---:|
| default-png | 5 | 10.1 | 24.0 | 71,184 |
| scale2-png | 5 | 21.0 | 30.1 | 166,350 |
| custom800-png | 5 | 9.1 | 10.9 | 81,548 |
| a4-jpeg | 5 | 167.3 | 266.9 | 371,644 |
| jis-b4-landscape-jpeg | 5 | 221.5 | 293.3 | 566,319 |
| a4-svg-mm | 5 | 1.8 | 2.2 | 45,727 |

반복30회는 p50 187.4ms·p95 220.3ms·최대 261.1ms, 실패0·PNG SHA2561종·미해제 ObjectURL0·DOM 노드 증가0이다. JS heap 표본은10회32.1MiB→20회20.9MiB→30회31.6MiB로 단조증가를 보이지 않았다. **강제 GC·heap snapshot·native/GPU 메모리 및 장기 leak 검증은 아니다.**

측정한 Canvas 최대 단일 면적은13,047,465px(JIS B4)로 RGBA 한 장 약49.8MiB에 해당한다. 최종 브라우저 메모리 상한은 아니다. width최대4299와 height최대3508은 서로 다른 출력의 독립 최대값이다.

벤치마크 페이지 전체에서 long task119개·최대178ms를 관찰했다. capture·엔진과 fixture의 pixel/digest 작업을 완전히 분리한 측정이 아니므로 전부 제품 지연으로 귀속하지 않는다. 사용자 이벤트 기반 캡처에서도 주스레드 정지가 생길 수 있으며, 저사양·빈번한 자동 캡처의 성능은 보증하지 않는다.

## 용지 규격 대조

ISO216:2007 원문 Table1/2의 A3/A4/A5·B3/B4/B5 치수를 공개 국가표준기관 preview에서 대조해 현재 표와 일치함을 확인했다. [ISO 공식 규격 정보](https://www.iso.org/standard/36631.html), [ISO216 원문 preview Table1/2, p5](https://preview.sist.si/sist-preview/36631/c0883203ea25445c9992bb09343620c5/ISO-216-2007.pdf).

JIS P0138:1998은 [JSA 공식 catalog](https://webdesk.jsa.or.jp/books/W11M0090/index/?bunsyo_id=JIS+P+0138%3A1998)에서 규격명·유효 상태를 확인했다. catalog에는 치수 표가 없고 공개 원문 preview를 확보하지 못해 **JIS 원문 치수 대조는 미완료**다. 구현표와24개 출력 기하의 일치만으로 원문 검토 완료를 선언하지 않는다. 유료 표준 구매는 하지 않았다.

## 잔여 항목·승인

1. JIS 원문 치수 대조를 완료해야 현재 release-readiness의 용지 확인 항목을 닫을 수 있다.
2. npm audit의 외부 npm registry 전송은 자동 승인 검토에서 거절되었다. 의존성 트리와 private 패키지 메타데이터 전송 가능성이 사유다. 해당 실행의 명시 승인은 비동기로 요청했으며 답변 전에는 재시도하지 않는다. 취약점 조회 결과가 없는 상태이므로 취약점0건으로 기록하지 않는다.
3. 실제0.0.1 버전·공개 설정·소스 commit 고정과 승인된 publish 절차가 남아 있다. 이번 tarball은 private dev 후보이며 배포 artifact가 아니다.
4. Safari는 기존 shadow/clip 실패로 정식 지원에서 제외하며 이번에 실행하지 않았다. Edge/Firefox·실제 모바일·저사양·장기 leak·범용 보안 감사는 미실행이다.
