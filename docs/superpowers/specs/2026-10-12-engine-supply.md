# 외부 엔진 수정본 공급 계약

## 결정과 범위

2026-10-12 유지관리자가 가버넌스에 위배되지 않으면 고정 버전 최소 수정본을 패키지 내부에 포함하는 권고안을 승인했다. Comins Contract v1.8 및 OSS_LICENSE_POLICY의 Distributed And Copied Material 기준에 따라 출처·버전·수정 표시·원문 라이선스를 보존한다. 설치된 SnapDOM 3.2.0의 MIT 메타데이터와 기존 원문 기록을 기준으로 이 방식에 적용되는 정책상 금지 조건은 확인되지 않았다. 법적 분쟁 부재를 보증하는 판단은 아니다.

현재 범위는 재현 가능한 빌드 공급 경로와 호출별 내부 확장 계약이다. 일반 DOM 준비·검증·공개 API를 완성한 것으로 간주하지 않는다. 기존 lab adapter와 연구 결과는 유지하며 원격 fork 게시, upstream 제안, npm publish는 수행하지 않는다.

## 공급 방식

- 설치된 고정 3.2.0 배포본을 입력으로 사용한다. 입력 SHA-256·원문 LICENSE·버전이 기준과 다르면 빌드를 중단한다.
- 기존 실증의 세 함수·다섯 지점만 변경한다. 빌드 생성기는 기존 TypeScript parser로 함수 범위를 식별하고 교체 횟수를 검증한다. minified 식별자를 안정 API로 취급하지 않는다.
- 생성물은 dist/engine/vendor에 위치한다. 상대 import로 Comins 확장 runtime을 참조한다. 연구 서버 URL에 의존하지 않는다.
- 같은 디렉터리에 원문 LICENSE, 출처·수정 지점·해시 provenance를 포함한다. 패키지에 THIRD_PARTY_NOTICES.md를 포함한다. 설치 엔진과 lockfile은 수정하지 않는다.
- 소비자 설치 시 패치를 실행하지 않는다. Comins 빌드에서 생성한 파일을 배포하며, 공개 exports는 유지한다.
- 라이선스 검사는 설치된 원본과 생성물·고지·런타임 연결을 함께 확인한다. 최종 tarball의 파일 목록·라이선스·비밀정보 확인은 실제 릴리즈 단계에 수행한다.

## 호출별 확장 계약

엔진 전역 상태 대신 capture context에 호출별 session을 전달한다. session은 준비 단계가 제공하는 얕은 복제 함수와 사전 승인된 이미지 데이터 URI 목록을 사용한다. URL 정규화와 바이트 형식 검증은 준비 계층의 책임이며, session은 정확한 URL 키와 승인된 PNG/JPEG/WebP 데이터 URI만 조회한다. 이 계층에서는 네트워크 fetch 또는 소비자 resolver를 호출하지 않는다.

복제 함수는 새로운 detached 노드를 반환해야 하며 원본 자신을 반환할 수 없다. 구체적인 custom tag 대체와 스타일·의미 보존은 준비 계층의 후속 책임이다. 연구용 div 대체를 모든 일반 DOM에 적용하지 않는다.

미등록 자원, 복제 실패, 취소, 종료 상태를 발견하면 해당 호출의 실패를 고정한다. 엔진이 예외를 삼켜도 session의 완료 검사가 실패해야 한다. raw URL·엔진 오류 원문은 공개 진단에 보존하지 않는다. session 간 상태·자원 목록은 공유하지 않으며 입력 목록을 복사한다.

이 확장은 pseudo 이미지와 얕은 복제 지점만 제어한다. 일반 IMG·폰트·SVG 등 다른 엔진 요청 경로를 모두 중재하는 기능이 아니다. G1/G3 충족과 공개 capture 연결은 별도로 남는다.

## 다음 제품 연결에서 반드시 해소할 사항

현재 CaptureStages.verify는 진단만 반환하고 createSnapshot은 engine artifact의 SVG와 renderTile을 계속 사용한다. lab adapter의 nativeTile도 원래 엔진 결과를 보유한다. 최종 SVG 치환본을 별도로 만든 뒤 진단만 통과시키면 PNG/JPEG/WebP/타일은 원본 결과를 사용할 수 있다.

따라서 다음 통합에서는 raw capture artifact와 검증 후 고정 output artifact를 분리하고, 모든 출력이 같은 검증된 SVG를 사용하도록 해야 한다. 검증 실패·취소 시 양쪽 artifact 소유권과 늦은 결과 정리를 검사한다. 엔진 원본 캔버스를 fallback으로 사용하지 않는다. 이 변경은 본 공급 단위에 억지로 포함하지 않고 일반 DOM 준비·SVG 검증 통합과 함께 수행한다.

## 완료 기준과 순서

1. 고정 입력 변경 시 생성 거부, 결정적 생성, 원문 라이선스 보존을 테스트한다.
2. 호출별 자원 격리, 미등록 자원 거부, 오류 삼킴 이후 실패 유지, 취소 및 종료 이후 접근 거부를 테스트한다.
3. 빌드 생성·라이선스 검사를 기존 verify에 연결한다. root import와 공개 타입은 변경하지 않는다.
4. 타입·빌드·unit·consumer·라이선스 전체 게이트 및 기존 연구 기록 회귀를 실행한다.

테스트 대역 성공을 실제 DOM/브라우저 출력 검증으로 보고하지 않는다. 새 생성물을 실제 제품 adapter로 연결할 때 Chrome·native Safari 출력 및 G1–G4 회귀를 다시 수행한다.
