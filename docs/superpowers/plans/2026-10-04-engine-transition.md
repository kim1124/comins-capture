## Global Constraints

- 초기 제품 범위는 PNG/JPEG/WebP/SVG·Canvas, 사용자 크기·ISO/JIS 용지·crop·고정 타일, Vanilla·React·Vue·Svelte이다. PDF·녹화·WebView·의미 단위 분할은 후속이다.
- 일반 래스터 CSS 1배, paper 300 PPI·기본 ISO, DPR은 명시 선택. 기존 오류·네트워크 deny·원본 보존·메모리 한도를 유지한다.
- 엔진 API·타입·플러그인·캐시·원시 오류를 공개 API에 노출하지 않는다. 제품 소스의 외부 엔진 import는 adapter 내부에 한정한다.
- 외부 엔진의 반환 이미지가 자체 엔진의 정답이 아니다. 해당 브라우저의 실제 원본과 Comins 계약을 기준으로 각각 판정한다.
- 앱 전역 fetch patch, 원본 marker, opaque cache 의존, 보안 정책 완화, 조용한 축소·엔진 fallback을 사용하지 않는다.
- 제품 완성은 초기 기능·지원 검증·패키지 준비 완료를 의미한다. npm publish·원격 쓰기·유료 서비스 도입은 별도 명시 승인 경계를 유지한다.
- 현재 Git·npm 제품 기준선이 없다. 기존 문서와 UUID 증거를 보존한다. 계획 문서 변경으로 제품 코드·실행 결과를 생성한 것으로 보고하지 않는다.

## 첫 릴리즈에 필수인 교체 구조

- Comins 공개 API·타입에 외부 엔진 옵션·반환 객체·플러그인 타입이 노출되지 않는다. 엔진 import와 호환 처리는 내부 adapter에 한정한다.
- `EngineAdapter`와 `EngineArtifact`는 Comins 소유 계약이다. capture·출력·타일·취소·dispose가 사용하는 의미와 자원 소유권을 정의하고 특정 엔진의 내부 캐시/노드 구조를 요구하지 않는다.
- 크기·용지·오류·수명주기·프레임워크 소비는 엔진 구현과 분리한다. 엔진에 맡길 수 있는 DOM 복제·스타일 계산을 미래 교체만을 위해 Comins에 중복 구현하지 않는다.
- 외부 엔진 adapter에 공통 계약 테스트를 적용하고, 제어 가능한 테스트 대역으로 orchestration의 결합을 검사한다. 테스트 대역의 성공은 실제 캡처 품질 증거가 아니다. 두 번째 실동작 엔진 구현은 첫 릴리즈 조건이 아니다.
- 원본 기준·출력·오류·자원 요청 증거를 구현 중부터 보존한다. 자체 엔진 상세 설계와 범용 확장 체계는 후속으로 둔다.

- [ ] 단계 3 자료와 제품의 확정 contract를 입력으로 자체 엔진 상세 명세·구현 계획을 작성한다. 현재 단계에서는 자체 엔진 제품 코드를 만들지 않는다.
- [ ] 기존 `EngineAdapter`를 구현하며 공개 API·크기 계산·자원 정책·프레임워크 연동을 재사용한다. 외부 코드를 복사하는 구현과 독립 구현을 구분해 라이선스 검토한다.
- [ ] 개발용 비교 실행에서 두 엔진을 동일 fixture에 적용한다. 필수 자원·보안·형식·크기·원본 보존 위반은 모두 실패로 판정한다.
- [ ] 시각 결과와 반복 성능·메모리를 비교하고 자체 엔진의 장점·회귀·지원 공백을 기록한다. 구체적인 성능 예산은 단계 3 기준 측정 후 전환 승인 전에 확정한다.

**완료:** 기존 제품 계약을 충족하고 전환에 필요한 비교 증거 확보. 두 엔진이 서로 같은 이미지를 출력하는 것만으로 완료하지 않는다.

## 단계 5: 검증된 자체 엔진으로 교체

- [ ] 공개 API·타입·오류·기본값·지원 범위의 호환성 차이를 검토하고 SemVer에 따라 전환 버전을 정한다. 차이가 있으면 문서와 변경 기록에 명시한다.
- [ ] 내부 기본 adapter를 교체하고 전체 계약·브라우저·프레임워크·consumer·라이선스·보안·패키지 검증을 수행한다.
- [ ] 외부 엔진 의존성·번들·lockfile·고지를 실제 배포물에 맞춰 정리한다. 과거 배포물이나 남아 있는 복사 코드의 고지 의무가 사라졌다고 간주하지 않는다.
- [ ] 마지막 정상 외부 엔진 버전과 재현 증거를 보존한다. 전환 문제가 있으면 명시적인 패키지 버전 복귀로 대응하며 사용자 호출 중 자동 엔진 fallback은 추가하지 않는다.

**완료:** 검증한 전환 artifact 준비. 실제 공개 배포는 별도 승인 후 수행한다.

## 이번 계획 변경의 검증

계획·지침·결정 기록의 링크와 단계 간 선행 조건을 점검한다. 문서 변경만으로 기존 브라우저 결과를 갱신하거나 제품 테스트를 실행한 것으로 보고하지 않는다. 현재 다음 실행 대상은 단계 1의 G1 내부 연구인 [P0-A manifest 해결 순서](2026-10-04-resource-preparation.md)다.
